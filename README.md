# AI Mystery Room

An AI assisted mystery investigation platform built with React, Express, MongoDB, and Google Gemini. Users create fictional cases, review suspects and evidence, keep private notes, then make one final accusation to reveal the solution.

## Requirements

- Node.js 20 or newer
- MongoDB running locally or a MongoDB connection string
- Optional Google Gemini API key for AI generated cases

## Run locally

1. Copy `server/.env.example` to `server/.env` and set `MONGODB_URI` and a long random `JWT_SECRET`.
2. Optionally set `GEMINI_API_KEY` to use Gemini. Without a key, the app uses a deterministic sample case so the complete investigation flow works without an external AI account.
3. From the repository root, run `npm install` and then `npm run dev`.
4. Open `http://localhost:5173`.

## Deploy (Vercel + Render + MongoDB Atlas)

This setup hosts the React site on Vercel, the Express API on Render, and stores accounts and cases in MongoDB Atlas. Keep `GEMINI_API_KEY`, `JWT_SECRET`, and `MONGODB_URI` on the server; `VITE_API_URL` is a public frontend setting.

### 1. Push the project to GitHub

Commit and push this repository. Confirm `server/.env` is not tracked (`git status` should not list it). The `.env` files are ignored; use the example files only as templates.

### 2. Create a MongoDB Atlas database

1. Create an Atlas project and a free or paid cluster.
2. Create a database user and save its password.
3. In **Network Access**, allow connections from Render. For a first deployment you can use `0.0.0.0/0`; use tighter network rules if your hosting plan supports stable outbound IPs.
4. Choose **Connect → Drivers** and copy the URI. Replace the password placeholder, and include a database name, for example `ai-mystery-room`.

### 3. Deploy the API to Render

1. In Render, create a **Blueprint** from the GitHub repository. Render will read `render.yaml` and create the `ai-mystery-room-api` web service.
2. Set `MONGODB_URI` to your Atlas URI. For the first deploy, set `CLIENT_URL` to `https://example.com`; you will replace it with the real Vercel site origin after creating the frontend. Multiple allowed origins can be separated with commas.
3. Optionally set `GEMINI_API_KEY`. If omitted, case creation uses the built-in demo generator. `JWT_SECRET` is generated by the Render blueprint; do not replace it with a short or guessable value.
4. Deploy and wait for the health check. Visit `https://<your-render-service>.onrender.com/api/health`; it should return `{"ok":true}`. Copy the service's base URL.

### 4. Deploy the frontend to Vercel

1. Import the same GitHub repository in Vercel.
2. Set the **Root Directory** to `client`.
3. Set the environment variable `VITE_API_URL` to `https://<your-render-service>.onrender.com/api` (include `/api`).
4. Keep the build command as `npm run build` and output directory as `dist`, then deploy.
5. Copy the deployed site origin and replace the temporary value in Render's `CLIENT_URL` (for example `https://ai-mystery-room.vercel.app`, without a trailing slash). Redeploy/restart the API, then set `VITE_API_URL` in Vercel to the Render API URL and redeploy Vercel.

### 5. Verify the live app

Open the Vercel URL, register a test account, create a fictional case, add a note, and submit an accusation. If the browser reports a network/CORS error, check that `VITE_API_URL` points to the Render API with `/api`, and that `CLIENT_URL` exactly matches the Vercel origin including `https://` but with no path or trailing slash. Vite variables are embedded at build time, so redeploy Vercel after changing `VITE_API_URL`.

For a custom domain, add its origin to Render's comma-separated `CLIENT_URL` and redeploy the frontend with the API URL unchanged. Do not put server secrets in Vercel variables prefixed with `VITE_`.

The API runs on port 5000 by default. Its routes are under `/api`. Set `VITE_API_URL` in a client environment file to use a different API URL.

## MongoDB connection refused

The default `MONGODB_URI` uses a local MongoDB server at `127.0.0.1:27017`. MongoDB Community Server must be installed and running before the API starts. On Windows, install MongoDB Community Server and enable its Windows service during setup. If it is already installed, start the `MongoDB` service from Services or run `net start MongoDB` in an Administrator terminal. Then restart `npm run dev`.

To use MongoDB Atlas instead, replace `MONGODB_URI` in `server/.env` with the application's Atlas connection string and ensure the cluster has a database user and permits connections from your current IP address. Keep the URI and credentials in the server environment; do not put them in client files.

## Included features

- Email and password registration and login with bcrypt password hashing and JWT protected API routes.
- Dashboard, profile statistics, case history, and user owned case deletion.
- Scenario based case creation with difficulty selection and input limits.
- Gemini JSON generation with structure and relationship validation, one retry, and a built in demo generator fallback when no key is configured.
- Investigation room with suspects, structured chat records, witness statements, simulated CCTV evidence, notes, and final accusation.
- Private notes can be created, edited, and deleted.
- The solution stays private until the final answer is submitted. The backend compares the selected suspect to the stored culprit ID.

Generated images are optional in this MVP. Photograph evidence uses a textual description or prompt placeholder; CCTV is labeled as a fictional simulation. No image or video files are generated by the text model.
